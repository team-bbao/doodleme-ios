### 3-1. 한마디 행높이

`RF대충쓴준우체v3` 는 30pt 에서 **기본 행높이가 73** 이다 (세로 여백이 넉넉한 손글씨체).
`lineSpacing` 은 거기에 **더하기만** 하고, `AttributedString` 에 문단 스타일을 실어도
SwiftUI `Text` 가 **무시한다**. 둘 다 붙여서 화면을 재 보고 확인했다.

→ `Shared/View/FixedLineHeightText.swift` 가 `UILabel` 을 감싼다.
줄 상자를 좁히면 글자가 위로 붙어 잘리므로 `baselineOffset` 으로 되내린다.

같은 문구를 Figma 렌더와 나란히 놓고 밀도 최고점 사이를 재니 **둘 다 45** 로 같았다. (고치기 전 73.5)

### 3-2. 카드 뒷면 이름 레이블이 `.bold` 인 이유

코드가 이미 `.semibold` 였는데도 디자인보다 옅게 읽혔다.
Figma 가 지정한 글꼴(Inter)에 한글이 없어 폴백으로 그려지는데, 그 폴백이 iOS 의 `.semibold` 보다 굵다.

잉크량 비교 (같은 글자를 Figma 렌더와 맞대어 측정):

| | 잉크량 |
| --- | --- |
| Figma (Semi Bold) | 100% |
| 앱 `.semibold` | 84% |
| 앱 `.bold` | **93%** |

화면에서 보이는 굵기를 따라 `.bold` 로 뒀다. 스펙 글자대로 되돌리려면 한 단어만 바꾸면 된다.

## 4. 고친 버그 (재발하면 여기부터 보기)

### 4-1. 사진 저장을 누르면 앱이 튕겼다

```
dispatch_assert_queue_fail
  _swift_task_checkIsolatedSwift
    closure #1 in PostDetailView.saveDrawingToGallery()
      [PHPhotoLibrary _performCancellableChanges...]
        큐: com.apple.PHPhotoLibrary.changes
```

이 프로젝트는 **`SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`** 라 화면 안의 것이 모두 메인 액터에 묶인다.
`performChanges` 에 넘긴 클로저도 함께 묶이는데 PhotoKit 은 **자기 큐**에서 부른다 → Swift 6 이 앱을 끊는다.

→ 사진 앱에 쓰는 부분만 `nonisolated static func` 로 꺼냈다.

**같은 함정이 또 나올 자리**: 프레임워크가 백그라운드에서 부르는 클로저를 View 안에서 만들 때는
`nonisolated` 로 꺼내거나 `@Sendable` 을 붙일 것.

### 4-2. 저장되는 그림이 빈 종이가 될 뻔했다

`ImageRenderer` 로 `DoodleImageView` 를 굽고 있었는데, 그 뷰는 `.task` 로 그림을 늦게 채운다.
**화면에 붙지 않은 뷰에서는 그 `task` 가 돌지 않는다.**

→ `DoodleImageCache` 가 이미 구워 둔 `UIImage` 를 `UIGraphicsImageRenderer` 로 흰 바탕에 얹는다.

저장 결과 확인 (시뮬레이터 사진 라이브러리에서 파일을 직접 꺼내 측정):
1050x1170 (350x390 캔버스 @3x) · 바탕 `#FFFFFF` 98.6% · 네 귀퉁이 모두 흰색 · 획 1.18% · 알파 없음.

### 4-3. 프로필을 고를 때 메모 한 장이 사라졌다

고르는 동안 이미 프로필인 한 장을 목록에서 빼고 있었다.
두 장 가진 사람은 갤러리의 절반이 없어진다. → 필터를 걷어냈다.

### 4-4. 바꾼 프로필이 저장되지 않았다

`setProfilePost` 가 `isProfile` 만 바꾸고 저장하지 않았다.
자동 저장은 앱이 물러날 때를 기다리므로 그 전에 강제 종료되면 없던 일이 된다.
→ 그 메서드 안에서 `try? save()`. (프로필을 바꾸는 모든 길이 이 메서드를 지난다)

## 5. 따로 떼어 둔 것 — 갤러리 상단이 옛 프레임 기준

`GalleryPage` 의 헤더 상수가 아직 옛 `iPhone 17 - 1`(5:24) 을 근거로 한다.
그 아래 세그먼트·그리드는 최신 `17 - 12/13` 을 따르고 있어 세로 리듬이 어긋난다.

- 지금 코드: `profileDiameter = 110`, `headerTopInset = 140`, 세그먼트 아래 여백 20
- 옛 `17 - 1`: 프로필 원 116, y=150 / 세그먼트 y=352
- 최신 `17 - 12·13`: 프로필 원 106, y=154 / 이름 y≈281.6 / 세그먼트 y=331 / 그리드 y=403

시뮬레이터에서 재면 카드 그리드 윗변이 **379pt** 로 Figma 의 403 보다 24pt 위에 있다.
최신 기준으로 맞추면 세그먼트 아래 여백도 20 이 아니라 33 이 된다.

화면 전체가 눈에 띄게 내려가는 변경이라 손대지 않았다.

## 6. 검증하지 못한 것

**상대를 찾은 뒤의 화면 전부.** 기기가 둘 필요하다.

- 찾은 사람 목록이 상태 문구 아래에서 **위에서 아래로** 쌓이는지 (Figma `17-19/20/4`, y572 고정)
- 네 명째부터 카드 안에서 밀어 볼 수 있는지, 그때 스크롤 막대가 보이는지
- 「전송됨」이 될 때 파란 테두리가 12시에서 한 바퀴 그려지는지 (`SentRing`)
- 그림을 받는 순간의 동작

수신 쪽 코드 경로는 `receivedCount` 변화 → 저장 → `onReceived` → `onClose` 순인데,
실제 수신 타이밍에서 `fullScreenCover` 가 깔끔하게 닫히는지, 스크롤이 제자리에 서는지는 확인하지 못했다.

사람이 없으면 카드 자체가 뜨지 않아, 목록 배치도 눈으로 보지 못했다.
못 찾음 화면(다시 찾기·설정 열기)이 그대로인 것만 확인했다.

**한 번에 보이는 사람은 세 명**(`visiblePeerLimit`)이고, 찾는 인원 자체에는 상한이 없다.
네 명째부터는 카드 안에서 밀어서 본다. 카드 높이를 세 줄로 묶어 둔 것은
그 아래가 화면 밖이라 눌러 보낼 수가 없었기 때문이다.

> 시뮬레이터를 두 대 띄우면 이 맥의 GPU 에 부담이 된다. 실기기 두 대로 확인할 것.

### 자잘하지만 다시 밟기 쉬운 것

- `LinearGradient` 상수를 **저장 프로퍼티로 두면 Swift 6 이 막는다** — `Color` 상수들이 메인 액터에 묶여 있다.
  `@MainActor` 계산 프로퍼티로 둘 것.
- `.fill(.doodlePaperFace)` 는 안 된다. `ShapeStyle` 에서 찾기 때문. `.fill(LinearGradient.doodlePaperFace)`.
- 글꼴 파일명은 ASCII 로 (`RFjunwooo.ttf`). 번들 안에서 한글 파일명은 정규화 때문에 못 찾는 일이 있다.
- 메모지 에셋 세 개가 모두 쓰인다 — `memoFront`(본체+삼각형) · `memoFrontMask`(본체만) · `memoBack`(그늘 참고용).
  삼각형만 떼어내려면 `memoFront` 에서 `memoFrontMask` 를 `destinationOut` 으로 지우면 된다.
